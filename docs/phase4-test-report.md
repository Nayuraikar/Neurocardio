## How numbers are checked

Each statistic on screen carries a `data-source` attribute. The checker resolves it from the files on disk (and, for stored counts, with its own SQL), formats it the same way and compares the text. Any other digit on the page fails the check unless it is in this allow-list:

- area `svg`: chart axis ticks and waveform axis labels
- area `[data-testid="activity"] table`: timestamps and file names of stored events (not statistics)
- area `[data-testid="record-browser"]`: per-record browser, checked separately against the WFDB annotations
- text `Macro-F1|macro-F1|\bF1\b`: metric name
- text `\bde Chazal DS2 without record 202\b`: name of a published partition (checked by the API against the split file)
- text `\bDS2\b|\btest_ds2\b|\bds2\b`: data-set name
- text `ResNet1D|resnet1d`: model name
- text `\bSHA-256\b`: hash algorithm name
- text `95% confidence intervals|95% CI`: method constant (artifact key ci95)
- text `\b2 s windows?\b`: window length constant (config)
- text `\brecord 202\b`: record identifier in a fixed caveat (it is a validation record in the model config)
- cells `5%` and `10%` in the study review table: review budgets (artifact keys)

Study numbers are compared with the committed reports in `backend/artifacts/analysis/`. A match shows that the page displays what the file says. It does not show that the evaluation behind the file is correct; that was not re-run.

The "perturbed copy" checks edit copies of those reports in a temporary directory. The committed files are not modified.

`npm run e2e` rewrites this file. Notes added by hand belong in the section it appends from `frontend/e2e/report-notes.md`.
